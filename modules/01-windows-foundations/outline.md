

## Outline

| Module | Lesson   | Proposed Lesson Title                                          | Short Description                                                                                                                                                                                        |
| ------ | -------- | -------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **1A** | **1.1**  | **Why Native Code Matters for Windows Internals**              | Establishes why C is the primary learning language for the course, where Rust fits, and why native code is the clearest lens for understanding Windows execution, memory, and low-level API interaction. |
|        | **1.2**  | **Building the Lab: Toolchain, Compilers, and Project Layout** | Sets up MSVC, MinGW-w64, and basic project structure so students can compile, inspect, and iterate without friction from environment issues.                                                             |
|        | **1.3**  | **Your First Windows C Program**                               | Introduces `windows.h`, a minimal WinAPI program, import linkage, and the basic compile-run-inspect loop that the rest of the module will build on.                                                      |
|        | **1.4**  | **Core C Types, Pointers, Arrays, and Addresses**              | Gives the learner the minimum raw-memory literacy needed to reason about buffers, addresses, pointer arithmetic, and how code interacts with memory.                                                     |
|        | **1.5**  | **Strings, Buffers, and Unicode on Windows**                   | Covers `char*` vs wide strings, raw byte buffers, string APIs, and why Windows string conventions matter before students touch more complex WinAPI usage.                                                |
|        | **1.6**  | **Structs, Packing, Alignment, and Data Layout**               | Builds the mental model for how C data is represented in memory, preparing students for PE headers, WinAPI structures, and parsing binary data later.                                                    |
|        | **1.7**  | **Function Calls, Calling Conventions, and Error Handling**    | Introduces function prototypes, callbacks, calling conventions at a conceptual level, return-value patterns, and `GetLastError`-style reasoning.                                                         |
|        | **1.8**  | **Heap Allocation, Runtime Choices, and Repeatable Builds**    | Combines `malloc`/`HeapAlloc`, CRT vs process heap, MSVC vs MinGW tradeoffs, and a first pass at CMake/Ninja so the learner can scale beyond toy programs.                                               |
| **1B** | **1.9**  | **Processes, Threads, and Execution Context**                  | Explains how Windows represents a running program: address space, primary thread, instruction flow, scheduler basics, and why threads matter operationally.                                              |
|        | **1.10** | **User Mode, Kernel Mode, and the Syscall Boundary**           | Clarifies privilege boundaries, what user-mode code can and cannot do, and how requests transition into kernel services.                                                                                 |
|        | **1.11** | **Virtual Memory, Regions, and Page Protections**              | Teaches the conceptual memory map of a process, including committed regions, stack vs heap, and why page protections matter to both engineering and detection.                                           |
|        | **1.12** | **Handles, Access Masks, and the Windows Object Model**        | Explains what handles really represent, how access rights gate operations, and why object access is central to later process interaction topics.                                                         |
|        | **1.13** | **Modules, the PEB/TEB, and Process Self-Knowledge**           | Introduces loaded modules, thread-local context, and the basic process bookkeeping structures students will later see in debuggers and reverse engineering work.                                         |
|        | **1.14** | **WinAPI, NTAPI, and the DLL Landscape**                       | Organizes the Windows API surface into usable mental buckets so learners understand where common functionality lives and how layers relate.                                                              |
|        | **1.15** | **Program Startup Path: A Lightweight Loader Preview**         | Gives only a high-level preview of how execution begins, enough to connect runtime concepts now without diving into full loader mechanics too early.                                                     |
| **1C** | **1.16** | **From Source File to Object File to Executable**              | Walks through the compilation pipeline so the learner sees how C code becomes machine code, object files, and then a final PE image.                                                                     |
|        | **1.17** | **Linking, CRT Startup, and Entry-Point Decisions**            | Explains what the linker contributes, what the CRT actually does, and how subsystem and entry-point choices affect program startup.                                                                      |
|        | **1.18** | **PE Headers, Sections, RVAs, and File Layout**                | Provides the core PE map: headers, section table, file offsets, and RVAs, so later loader behavior has a concrete structure behind it.                                                                   |
|        | **1.19** | **Imports, Exports, and the Import Address Table**             | Covers import resolution, export lookup, IAT structure, and why these tables are central to both execution and analysis.                                                                                 |
|        | **1.20** | **Relocations, ASLR, and Address Fixups**                      | Builds the learner’s model for preferred image bases, relocation processing, and why binaries cannot assume fixed addresses in modern systems.                                                           |
|        | **1.21** | **PE on Disk vs Image in Memory**                              | Compares the file as stored with the image as mapped, helping students understand why debuggers, loaders, and static tools do not always show the same thing.                                            |
|        | **1.22** | **How the Windows Loader Maps and Initializes an Image**       | Now that PE structure is understood, this lesson covers mapping, import resolution, relocations, TLS callbacks, and transfer of control in the right sequence.                                           |
|        | **1.23** | **Resources, Manifests, Metadata, and Signing**                | Closes the PE block with the non-core but still useful metadata layer: resources, manifests, and signatures as part of the binary’s broader identity.                                                    |
| **1D** | **1.24** | **x64dbg Orientation and First Inspection Workflow**           | Introduces the debugger interface, stepping, breakpoints, modules, and registers so the learner can navigate confidently before interpreting behavior.                                                   |
|        | **1.25** | **Registers, Flags, and the x64 Calling Convention**           | Teaches the minimum register model needed to understand argument passing, return values, control flow, and why certain registers matter more than others.                                                |
|        | **1.26** | **Stack Frames, Prologues, and Function Flow**                 | Builds from the calling convention into stack layout, prologue/epilogue patterns, locals, saved registers, and how functions are represented at runtime.                                                 |
|        | **1.27** | **Reading Common x64 Assembly Patterns**                       | Helps students read compiler-generated instruction patterns for moves, comparisons, calls, branches, loops, address calculations, and simple control flow.                                               |
|        | **1.28** | **Breakpoints, Memory Inspection, and Live State Changes**     | Focuses on observing and modifying runtime state: memory views, watchpoints, register edits, string inspection, and cause/effect during execution.                                                       |
|        | **1.29** | **Attaching to Running Processes and Exploring Live Modules**  | Extends debugging beyond launch-time analysis into process attachment, thread inspection, module views, and live runtime observation.                                                                    |
|        | **1.30** | **WinDbg Essentials for Research-Oriented Inspection**         | Gives a compact secondary-tool view so learners know when and why they would pivot from x64dbg into WinDbg for deeper process-structure visibility.                                                      |
|        | **1.31** | **Synthesis: Following a Program from Source to Mapped Image** | End-of-block integration lesson that ties together code, compiler, PE layout, loader behavior, process memory, and debugger observations into one coherent mental model.                                 |
