
## Outline

|Module|Lesson|Proposed Lesson Title|Short Description|
|---|---|---|---|
|**3A**|**3.1**|**Remote Execution on Windows: Targets, Boundaries, and Access**|Introduces the overall remote-process problem space, including why cross-process interaction is possible, what rights gate it, and how integrity level, UAC, and privilege context affect success.|
||**3.2**|**Process Enumeration Fundamentals**|Covers the major ways Windows processes can be enumerated, what information is typically gathered, and how students should think about target discovery as a data-collection step rather than a single API call.|
||**3.3**|**Choosing a Stable Target Process**|Adds a deliberate target-selection lesson focused on architecture, session, privilege level, process role, and stability so learners understand why some targets are more practical than others.|
||**3.4**|**Opening Remote Processes and Requesting the Right Access**|Frames `OpenProcess` and access masks as precision tools, emphasizing least-necessary rights, common failure modes, and how handle acquisition connects back to earlier Windows object and access-mask concepts.|
||**3.5**|**Enumerating Threads and Understanding Execution Surfaces**|Explains thread discovery, thread ownership, and why threads are the real execution surfaces inside a target process, preparing learners for APCs, hijacking, and other context-based techniques later.|
||**3.6**|**Reading Remote State: Memory, PEB/TEB, and Basic Verification**|Uses remote state inspection conceptually to show how students validate assumptions about a target process, including module presence, strings, basic structure reads, and pre-injection sanity checks.|
|**3B**|**3.7**|**Remote Memory as a Lifecycle: Reserve, Write, Protect, Verify**|Establishes the full lifecycle of remote memory manipulation so students see allocation, writing, protection changes, verification, and cleanup as one coherent pipeline.|
||**3.8**|**Allocating Memory in a Remote Process**|Covers remote allocation at a conceptual level, including placement, size, alignment, and protection planning, while reinforcing the difference between local and remote address spaces.|
||**3.9**|**Writing Data and Code into Remote Memory**|Frames `WriteProcessMemory` as a generic remote-transfer primitive for strings, configuration data, and code buffers, with attention to verification and partial-write considerations.|
||**3.10**|**Protection Transitions and Executable Memory Hygiene**|Focuses on protection changes such as RW to RX, why permission transitions matter operationally, and how memory protection choices shape both stability and visibility.|
||**3.11**|**Section Objects and Shared Mapping Concepts**|Introduces section-backed memory and shared mapping as a distinct model from heap-style remote allocation, giving students a second mental model for moving bytes between processes.|
||**3.12**|**Observing Remote Memory with Debuggers and Inspection Tools**|Teaches learners how to validate their work through runtime observation, using memory views and process-inspection tools to confirm allocation, placement, protection, and resulting artifacts.|
|**3C**|**3.13**|**Injection Families: A Comparative Mental Model**|Opens the injection block by organizing major technique families by their execution trigger, memory model, and artifact profile so students understand the landscape before individual variants.|
||**3.14**|**CreateRemoteThread as the Baseline Remote Execution Pattern**|Uses remote thread creation as the foundational model for cross-process execution because it cleanly demonstrates the full chain from handle acquisition to memory placement to execution trigger.|
||**3.15**|**DLL Path Injection and Standard Loader-Mediated Execution**|Presents loader-assisted DLL execution as the Windows-native baseline for module-based injection, highlighting how it differs conceptually from raw shellcode execution.|
||**3.16**|**APC-Based Dispatch and Alertable Execution Contexts**|Introduces APC-driven execution as a context-dependent dispatch model, emphasizing the importance of thread state and why not all execution mechanisms create brand-new threads.|
||**3.17**|**Thread Hijacking and Execution Context Redirection**|Teaches suspend/inspect/redirect/resume as a distinct family where an existing thread is repurposed, making execution context a first-class topic rather than an implementation detail.|
||**3.18**|**Section-Based and Mapped-View Injection**|Builds on the section-object lesson to show how mapped views create a different injection surface, helping students compare private allocations with shared-memory execution patterns.|
||**3.19**|**Manual Mapping and Reflective Loading Concepts**|Moves loader-bypass module execution into a later position, after students already understand standard DLL loading and remote memory control, so reflective and manual mapping land with the right prerequisites.|
||**3.20**|**sRDI and Shellcode-Wrapped Module Execution**|Positions sRDI as a bridge between shellcode and DLL models, helping learners understand how module logic can be repackaged into a more self-contained execution form.|
||**3.21**|**Comparing Injection Techniques: Dependencies, Artifacts, and Tradeoffs**|Consolidates the whole injection block by comparing technique families in terms of required privileges, runtime assumptions, execution context, and observable side effects.|
|**3D**|**3.22**|**Suspended-Process Creation and Hollowing Fundamentals**|Reframes hollowing around the idea of starting a process in a controlled state and altering what ultimately runs inside it, making image replacement easier to understand conceptually.|
||**3.23**|**Startup-Phase Execution: Early Bird and Related Timing Variants**|Groups early-start techniques around process startup timing, showing why “when execution begins” can matter as much as “how execution begins.”|
||**3.24**|**Image Replacement Variants: Hollowing, Doppelgänging, and Herpaderping**|Organizes the image-replacement family into one comparison lesson so students understand the shared theme first, then the major conceptual differences between variants.|
||**3.25**|**Module Stomping and In-Image Reuse**|Introduces the idea of reusing already-loaded image space as a host, helping students compare new-memory allocation with techniques that blend into existing module structures.|
||**3.26**|**PPID Spoofing and Parent/Child Relationship Manipulation**|Covers parent-process manipulation as a startup and lineage-control concept, keeping it clearly separated from code-execution mechanics while still connecting it to process creation workflows.|
||**3.27**|**Command-Line, Image, and PEB-Based Masquerading**|Groups command-line spoofing, image-name changes, and related PEB/loader metadata tricks into one coherent lesson on surface-level process identity manipulation.|
||**3.28**|**Header Stomping and Post-Load Artifact Reduction**|Treats PE-header modification as an artifact-management topic, focusing on what changes in memory representation and what that does or does not meaningfully conceal.|
||**3.29**|**Execution Context Crafting and Threadless Dispatch Concepts**|Closes the module with a higher-level lesson on context restoration, alternate dispatch, and threadless-style execution ideas, positioning them as advanced context-control concepts rather than baseline techniques.|
||**3.30**|**Synthesis: Selecting the Right Remote Execution Strategy**|Final integration lesson that compares all of Module 3’s approaches through the lenses of prerequisites, stability, process impact, and observability so the learner leaves with a usable decision framework.|
